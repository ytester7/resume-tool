# resume-tool 项目体检报告与迭代规划

> 版本基线：v2.1.0（commit 7f65ae7）· Vue 3 + TS + Vite + Pinia 本地优先简历编辑器
> 规模：src 48 TS / 37 Vue，约 4400 行；13 套模板；单测 + E2E 齐备

---

## 一、现状盘点（做对了什么）

| 维度 | 现状评价 |
|---|---|
| 架构 | 编辑器 / 预览 / 存储三层解耦干净，Pinia store 职责清晰（tabs / fileSystem / ui） |
| 存储 | File System Access API + IndexedDB + localStorage 三层兜底，降级路径完整 |
| 稳定性 | 异步模板懒加载统一 loading/error 兜底，`onErrorCaptured` 防白屏；启动崩溃恢复 |
| 质量 | 18 个 spec 文件，`vue-tsc` strict + ESLint + Playwright 全绿 |
| 差异化 | **简历健康度评分**（5 维度 100 分 + 可点击跳转建议）——这是全项目最有价值的资产 |

结论：**这是一个"工程质量优秀但产品闭环不足"的项目**。地基打得很结实，房子却只盖了一层。

---

## 二、缺点分析

### A. 易用性（当前最痛）

| # | 问题 | 具体证据 | 影响 |
|---|---|---|---|
| A1 | **空状态是死胡同** | `App.vue` 空编辑器只提示"请点击新建"，`defaultResumeData()` 全空，无示例数据、无引导 | 新用户打开面对一片空白表单，0→1 转化极低。这是 resume 类产品的生命线 |
| A2 | **无导入现有简历** | 打开仅支持自家 JSON（`parseResumeFile`），用户手里是 PDF/Word/旧平台 JSON，全部要手敲 | 最大流失点。用户不想从零填 |
| A3 | **13 套模板无缩略图预览** | `TemplateSection.vue` 只有文字列表，`[` `]` 快捷键盲切 | 选模板靠猜，无法感知视觉差异，13 个选择反而是负担 |
| A4 | **单栏固定 + 硬编码 380px** | `grid-template-columns: 380px 1fr`，无分栏拖拽调节 | 简历数据密度高时编辑区挤、预览小；宽屏浪费右侧空间 |
| A5 | **移动端仅"能用"** | <768px 垂直 45%/55% 堆叠，但工具栏按钮横排 5 个、编辑表单无折叠分组 | 手机上属于不可用级别 |
| A6 | **无撤销/重做** | 全项目搜不到 history/undo 栈 | 误删一条经历 = 重打，编辑器类产品的红线缺失 |
| A7 | **健康度仅本地规则** | `healthScore.ts` 全是硬编码正则与固定分值 | 分数"看起来很科学"但无法解释，用户不信服也无从改进 |

### B. 功能性

| # | 问题 | 说明 |
|---|---|---|
| B1 | **只能导出 PDF（html2canvas 光栅化）** | 质量损失 + 中文断行错位 + 超 2 页必糊。**缺打印级矢量 PDF 导出** |
| B2 | **无岗位定向** | 13 模板 + 6 色 + 5 字体，但没有"投后端/投设计/投管理"的分档，内容不会按岗位裁剪 |
| B3 | **无 JD 关键词比对** | 简历健康度只看"自身写得好不好"，不看"跟岗位匹配吗" |
| B4 | **无作品集/链接卡片** | 项目经历只有纯文本条目，无法附 GitHub/上线地址缩略展示 |
| B5 | **无多语言** | 全项目零 i18n，纯中文硬编码；但模板里有 european / english 风格存在 |
| B6 | **无版本快照/回滚** | 自动保存只覆盖"最后一次"，误改后无法回到昨天的版本 |
| B7 | **示例简历目录 `resume-builder/` 未被引用** | 仓库里躺着一整套旧实现，属技术债干扰源 |

### C. 创新性（最缺）

项目目前是"更好的本地 Word 替代品"，缺少不可替代的能力：

1. **AI 岗位适配助手**：粘贴 JD → 自动抽取关键词 → 提示哪些经历该重写、哪些技能该补
2. **STAR 智能改写**：把"负责后台接口开发"自动补全为量化 STAR 描述，直接喂给健康度的"量化度"维度
3. **多版本矩阵**：一份经历，针对 3 个岗位一键生成 3 个侧重不同的版本，Tab 管理已具备雏形
4. **面试官视角预览**：模拟 HR 6 秒快速浏览，标注"视线停留热点区"，用眼动热区启发式提示信息密度问题

## 三、迭代路线图

按 ROI 排序，分四期。建议 **P0 + P1 就能让产品质变**。

### P0 · 止血（1~2 周，投入小、感知强）

| 任务 | 目标 |
|---|---|
| 示例简历一键填充 | 内置 3 套完整示例（后端/测试/设计），空 Tab 默认提示"填充示例" |
| 撤销/重做 | 快照栈（数据量大时只存结构化 diff），`Ctrl+Z` / `Ctrl+Shift+Z`，TabBar 显示可撤销步数 |
| 模板可视化卡片 | 每个模板渲染真实缩略图（可用 `transform: scale` 截取现有组件），支持按 4 个 category 分组筛选 |
| 打印/PDF 双通道 | 保留 html2pdf 作兜底，新增 `@media print` 打印样式表 + `window.print()` 高保真通道 |
| 编辑区宽度可拖 | 分栏拖拽条 + 双击复位 |

### P1 · 闭环（3~5 周）

| 任务 | 目标 |
|---|---|
| **旧简历导入** | 支持 PDF（pdf.js 抽文本）/ Word / 通用 JSON 智能映射到字段，导入后进"待确认"高亮态 |
| **岗位定向 + JD 匹配** | 新增 `TargetJob`（岗位 + JD 文本），健康度新增第 6 维度"匹配度"，输出"缺失关键词 / 建议重写条目" |
| **分档内容建议** | 按岗位类型给出区块取舍建议（如投测试岗 → 隐藏"自我评价"、强化"项目经历"） |
| **版本快照** | 每日/手动快照，TabBar 右键菜单可回滚 |
| 移动端适配 | 工具栏折叠为抽屉 + 编辑区改为手风琴分组 |

### P2 · 差异化（6~8 周，需接云端或本地模型）

| 任务 | 目标 |
|---|---|
| **AI 改写助手** | 选中任意条目 → 一键 STAR 化 / 精简 / 换语气（走 WorkBuddy 云端大模型或用户自带 Key） |
| **多岗位版本矩阵** | 基于同一份主数据派生 N 个定向版本，Tab 隔离管理，导出时各自命名 |
| **面试官 6 秒视图** | 灰度遮罩 + 视线热区，提示"首屏应放最硬的三条经历" |
| 作品集链接卡片 | 项目条目支持 URL + 一句话定位，模板可选卡片式呈现 |

### P3 · 长尾

- 数据统计：哪套模板导出后打开率更高（纯本地，做成用户自持的 A/B 记录）
- 简历版本对比 diff 视图
- 打印稿裁剪辅助线

## 四、架构配套建议（随功能一起改）

1. **模板重复**：`ModernLayout`(177行) / `QaProLayout`(148行) / `ClassicLayout`(59行) 各写一遍 `shared/*` 之外的结构。建议引入 **模板声明式 schema**（section 位置 + 样式 token），模板退化为配置项，13 套可降到 2 个壳 + 配置。
2. **`healthScore.ts` 瘦身**：把规则常量抽成 `healthRules.ts`，让评分逻辑可被测试与用户自定义。
3. **清理 `resume-builder/`**：已废弃的旧实现，建议移出仓库或归档到 `archive/`。
4. **引入 `useUndoHistory` composable**：为 P0 的撤销能力预留统一入口。

## 五、优先级速查

```
立刻做（体验止血）      示例简历 · 撤销重做 · 模板缩略图 · 打印通道 · 分栏拖拽
        ↓
让人留下（功能闭环）    旧简历导入 · JD 匹配 · 岗位分档 · 版本快照 · 移动端
        ↓
让人记住（创新）        AI STAR 改写 · 多岗位版本矩阵 · 面试官 6 秒视图 · 作品集卡片
        ↓
顺手清理               模板声明式重构 · healthRules 拆分 · 删除 resume-builder/
```

**一句话结论**：项目不缺功能，缺的是"让新用户 30 秒内看到成品"的路径，以及"AI 让简历质量真的变好"的差异化。把示例数据 + 导入 + JD 匹配这三件事做完，resume-tool 就从"好用的编辑器"变成"不好用的替代品会被换掉、但不好用就没人用的工具"——差异就在这三个点上。
